Capitalization

We follow Microsoft style: sentence-style capitalization for everything, with two exceptions that come from SnapLogic itself. Capitalize the first word and proper nouns, and use lowercase for the rest.

Sentence case
The default for sentences, headings, titles, buttons, checkboxes, and labels.
Create a table if it doesn’t exist
Snap names
Written exactly as the Snap is titled. They are product names.
Snowflake - Bulk Load
SnapLogic terms
Capitalized as listed in Terminology, wherever they appear.
Snaplex, Triggered Task
Capitalize the first word of anything that stands alone
That covers sentences, headings, titles, UI labels such as the name of a button or checkbox, and standalone phrases.
Capitalize proper nouns, including brand, product, and service names
Reserve capitalization for names. Everything else is lowercase, including pipeline, account, asset, and control plane.
After a colon in a heading or title, capitalize the first word
Example: Error handling: Retry failed requests
Don’t capitalize the spelled-out form of an acronym
Unless it’s a proper noun. Example: single sign-on (SSO)
When words are joined by a slash, match the word before it
Capitalize the word after the slash if the word before it is capitalized. Example: Country/Region
No internal capitals unless it’s a brand name
AutoSync, AutoPrep, and FeedMaster are brand names, so they keep theirs. AutoScale as a generic word would not.
Don’t use all uppercase for emphasis, or all lowercase as a design choice
Pills and tags look uppercase because the component applies text-transform: uppercase. Write the string itself in sentence case.

Punctuation

Use a period for sentences and for strings that act as sentences
Example: Could not get server task result messages.
Don’t use a period for short labels
Example: Pipeline overview
If a list mixes full sentences and phrases, treat all of it as sentences
Every item ends with a period, so the list reads as one thing.
Be concise, even if the result is an incomplete sentence
Quickly scannable text matters more than a complete sentence.
Don’t end a title, heading, or UI title with a period or colon
Example: Move a tile, not Move a tile.
Use the serial comma
In a list of three or more, put a comma before the conjunction. Example: Android, iOS, and Windows
Use one space after a period, question mark, or colon
Use no spaces around a dash.
Dashes and hyphens follow Microsoft style
Use an em dash with no spaces around it to set off a phrase. Use an en dash for ranges of numbers and dates, and for a minus sign. Use a hyphen to join words and connect prefixes. Never use two hyphens in place of an em dash.
Use a colon to introduce definitions, explanations, and lists
Use parentheses for supplementary or optional information, and for abbreviations and acronyms.

Field names and checkboxes

Field names describe the contents. They don’t give instructions
When the design calls for an instruction, edit it so the label is as clear as possible. Example: Select existing credentials
Checkbox labels never use double negatives
It must be obvious what happens when someone selects the box. Write Log errors in a separate table, not Do not skip logging errors.
