markup
Build on a native <input type="range">. It supplies the keyboard model, the value announcement, and min / max / step for free. Drive the fill from a --pct custom property.
keyboard
Arrow keys move one step. Page Up/Down moves ten steps. Home/End jump to min/max.
accessibility
Label wired with for/id. A read-only readout carries aria-hidden="true" — the input already announces the value. Error and help text wired with aria-describedby.
hit area
Visual control remains 28px tall; the input is 44px tall and vertically centred, so the touch target extends past the visual without opening up the row.
widths
Fluid by default. Presets: 160 / 240 / 320px. Below 160px the track is too short to aim at — use a number input instead.
value display
Read-only readout in a fixed 44px column when the user only needs to see the landing value. Paired number input when exact values matter; the unit suffix goes in the input.
not included
No tick marks, value bubble, loading state, vertical orientation, or dual-thumb range variant in the base Slider. Vertical is deliberately out — every SnapLogic form is horizontal, and the usual implementation is a rotate hack that breaks the hit area.
don't
Don't use a slider for a handful of discrete options — use a radio group or segmented control. Don't use one where the exact number matters and no number input is paired.
