Usage

When to use
  • A long task that breaks into 3 or more ordered steps
  • Later choices depend on earlier ones
  • First-time setup where users need guidance
AutoSync setup · creating a Task · connection setup · first-time org config
When not to use
  • Fewer than 3 steps — use a single form
  • Non-linear editing, where users jump around — use form sections with Save
  • Simple data entry that fits on one screen
Editing an existing object is almost never a wizard.

Variations

Both use the vertical step rail. Pick the container by length.

Modal wizard

Opens in a large Modal. Keeps the user on one task until they finish or cancel.

  • Shorter flows, a few fields per step
  • Vertical rail inside the modal
In-page wizard

Fills the page content area. Title and description go in the page header.

  • Longer flows, or steps with substantial content
  • Leaving the page asks to confirm unsaved input

Behavior

Moving through steps
  • Next validates the step and stays disabled until it's valid. Never auto-advance.
  • Back keeps every value. It's disabled on the first step.
  • Going back never resets later steps.
Jumping between steps
  • Click a completed step to return to it.
  • Can't skip forward over uncompleted steps.
  • Hover deepens the dot to Blue 700; keyboard focus shows --shadow-focus-ring.
Leaving
  • Cancel or × with unsaved input asks to confirm before discarding.
  • Wizards of 5+ steps offer Save draft in the header. Drafts last 14 days and reopen at the last completed step.
Optional steps
  • Mark them (optional) in the step label.
  • When only optional steps remain, add a tertiary Skip to review button beside Back.

  • Review lists every input as label/value pairs, grouped by step, each group with an Edit link back to that step.
  • The final primary button names the result: Create task, Start sync — never "Finish" or "Submit".
  • Long-running submit: the body shows a progress bar and a short status message; footer buttons disable.
  • Done: the body shows a success or error message with one primary action (View AutoSync) and Close. On error, keep the user's input and offer Back to review.

Content

  • Wizard title: verb + object — Set up AutoSync, Create task.
  • Step labels: 1–2 words, sentence case, nouns (Source, Schedule). Optional sub-label shows the choice made or a hint.
  • Step titles: expand the label as a question or instruction — How often should this sync run?
  • The last step is always labelled Review.

Accessibility

  • The step rail is <nav aria-label="Steps">. The current step has aria-current="step"; locked steps are aria-disabled, never removed.
  • Completed steps are <button>s.
  • On step change, move focus to the new step title.
  • Validation errors are announced and focus moves to the first invalid field.
