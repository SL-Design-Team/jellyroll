Design principlesintent first · behavior second

Design for confident progress

Principles define the experience we want people to have. Behavior rules turn that intent into consistent decisions across components and patterns.

Design principles

the experience to optimize for
01

Defer nonessential decisions

Ask for a choice when it becomes relevant, not before. Start with sensible defaults and let people refine later.

02

Reveal complexity when needed

Lead with the essential path. Progressively disclose advanced settings, detail, and exceptions when they help someone complete the task.

03

Provide good defaults

Make the most likely successful path easy to accept. Defaults should be clear, editable, and based on useful context.

04

Make exploration reversible

Let people inspect, compare, and try changes without fear. Prefer preview, cancel, restore, and undo when the action can be recovered.

05

Give immediate feedback

Acknowledge every meaningful action right away. When work takes time, show what is happening and what will happen next.

06

Be consistent and predictable

Use the same language, placement, and response for the same kind of action. Familiar behavior reduces the effort of every later task.

07

Preserve progress in steps

Break complex work into manageable parts and retain what has already been entered. People should be able to pause, return, and continue.

08

Make frequent work fast

Support repetition with remembered choices, recent items, templates, and shortcuts—without hiding the standard path from occasional users.

Behavior rules

the decisions that apply everywhere
01

Make the result visible

Every meaningful action ends with a clear result. Show a durable change inline; use a toast for background completion or a reversible action. Never leave a person to infer whether work succeeded.

Action → visible result → next step
02

Keep the user in control

Do not discard work, navigate away, or close a task while its result is uncertain. Offer a safe exit when possible, preserve entered values, and make recovery obvious.

Preserve progress · explain consequences
03

Choose the least disruptive surface

Keep people in context whenever the task can be completed inline. Escalate to a focused layer only when a decision or task requires undivided attention. The relevant component page defines the mechanics.

Inline first · focused layer only when needed
04

Protect consequential actions

Name the object and consequence before asking someone to commit. Make the safe path clear. For recoverable removal, offer Undo; for permanent or broad-impact changes, require deliberate confirmation.

Specific object · safe default · recovery where possible
05

Make async work legible

Show progress as soon as work starts and prevent duplicate submission only for the active action. Keep unrelated controls available, surface a useful failure state, and offer Retry when someone can reasonably try again.

Pending → success or actionable failure
06

Put errors beside recovery

Keep invalid values in place and explain how to fix them next to the affected field or task. When several errors exist, add a summary that moves focus to the first problem.

Preserve input · describe fix · focus the first error
07

Design for keyboard and constrained space

Keyboard behavior follows the visual task order: Tab enters and leaves controls, arrow keys move within a composite control, Enter activates the focused safe default, and Escape dismisses only when dismissal is safe. At smaller viewports, reflow content before hiding it; focused content scrolls within its available space rather than beyond the viewport.

Native semantics first · visible focus always · responsive reflow before omission
