The words in buttons, fields, confirmations, empty states, and tooltips. Layout and behavior live in the components and patterns. This page covers what to write. For capitalization, punctuation, and wording, refer to Content guidelines and Terminology.

Buttons and actions

Start with a verb and keep it to one to three words
Save changes, Create pipeline, Run. Sentence case, no end punctuation.
Add the object when the verb alone is ambiguous or destructive
Delete pipeline rather than Delete when more than one thing could be deleted.
Avoid OK, Submit, and Yes/No
Name the action. The exception is a confirm where both choices are affirmative, such as No, don’t save and Yes, save.
Use Create and Delete for objects, Add and Remove for items in a collection
Create pipeline, but Add Snap to a pipeline.
Use Cancel to back out and Close when there’s nothing to cancel
Give icon-only buttons an accessible name that says the action
Delete, not Trash can.

Labels, placeholders, and help text

Always label a field with visible text 3.3.2
A placeholder is not a label. It disappears when someone types and is hard to read.
Placeholders show the shape, not an instruction
dd/mm/yyyy or Search Snaps, never Enter your name here.
Help text clarifies, and doesn’t restate the label
Use 8 to 64 characters. beats Enter a password.
Mark the exception
When most fields are required, mark the optional ones as optional. Say it in words, not with a symbol alone.
Don’t repeat the section in every label
Under a heading of Pipeline details, write Name and Owner, not Pipeline name and Pipeline owner.

Confirmations and feedback

Make a confirm’s button say the action
Delete pipeline and Cancel, never Yes and No. The safe action is the default.
Ask a question in the title, and name the object in the body
Title: Delete this pipeline? Body: name it, and say what happens to it and when.
Report a result in the past tense, briefly
Pipeline saved, Pipeline restored. Skip successfully. It adds nothing.
Name what is loading
Loading pipelines, not Loading alone.
Write each status so it makes sense read aloud on its own 4.1.3

Empty states

Say what the space is for, why it’s empty, and what to do
Title: No pipelines yet. Action: Create your first pipeline.
When a filter caused it, say so and offer the way out
No pipelines match your filters with a Clear filters action.
Keep inline empty states to one line
A short message and, if needed, one action.

Tooltips, headings, and navigation

Keep a tooltip to one short sentence
Don’t repeat the visible label, and never put the only copy of important information in a tooltip.
Write headings that describe their content 2.4.6
Sentence case, no end punctuation, key word first. Connection settings, not Settings for your connection.
Use a noun for a section and a verb for a task
Pipelines is a place. Create pipeline is an action.
Match a navigation label to the page it opens 3.2.4
If the nav says Monitor, the page title says Monitor. Use one name for one thing everywhere.
