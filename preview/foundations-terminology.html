Usage notes

How to choose between similar words, and a few rules that apply to a single term.

TermGuidance
allowsUse when you permit the user to do something: “The Password field allows you to enter alphanumeric values.” If you can swap in permits, use allows.
enablesUse when you mean provide with the means or opportunity. If you can swap in empowers, use enables.
alternativeUse for choices.
canUse when ability is what you’re expressing: actions the reader or program is able to do.
shouldA recommended, optional action, not a probability. “You should drop the table before trying to reload.”
mustAvoid. Exception: your code must catch and handle errors.
need to, have to, requiredUse for a requirement or obligation. “You need to retrieve the API key before you configure the YAML file.”
if, whether, that, whichUse if for a condition and whether for uncertainty. Use that for a specific object, item, person, or condition, and never omit it. Use which to add information, with commas before it and at the end of the clause.
when, whileUse when for situations that need preparation or for the passage of time. Use while only for simultaneous actions or contrast. Otherwise use and, when, although, or whereas.
specific, specifiedUse specific to highlight distinct characteristics: “import specific assets, such as pipelines”. Use specified for something that has been defined: “the specified parameters configure the JVM”.
compared to, compared withUse compared to when one thing is seen as superior to another; it can read as negative. Use compared with for neutral comparisons.
data isUse is, not are.
data set, field setTwo words for general references. One word for the HTML element.
learn moreUse for general information or when a link covers more than one topic. Prefer an inline link that tells people what they’ll find. A short lead-in makes it clear when the content is outside our own sites.
log in, log outTwo words as verbs. One word, login and logout, as nouns.
now, previouslyAvoid. Describe changes so they don’t go out of date, because the feature might change again.
pleaseUse only when our system is at fault and we need the user to do something: “Failed to retrieve data, please try again.” When documenting a UI string that contains please, copy it as written.
update, upgradeUpdate is for patches. Upgrade is a change to the next full version.
upsertUse for the update/insert database operation. Our audience knows it.
usernameWhen you’re referring to a specific label, use the spelling in the UI.
nodeApplies to many concepts in programming and networking, so be specific. Refer to Snaplex node.
vs.In headings, the abbreviation vs. in lowercase. In text, spell out versus.
weUse we, the first person plural, when referring to SnapLogic.
backward compatibleHyphenate only when it modifies something: “backward-compatible features”.
wildcardDon’t use on its own. Use as a modifier with terms such as character, certificate, functionality, patterns, search, or tables.
dashes and hyphensRefer to Punctuation in Content guidelines.
prefixesFollow the Microsoft Style Guide on prefixes and hyphens. For words it doesn’t list, check a dictionary.
product namesDo your research. Don’t just accept what Dev provides. Check the company’s own website for the actual product name.
